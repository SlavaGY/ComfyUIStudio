# Imagine в составе ComfyUIStudio — что сделано

Imagine (карточный веб-генератор поверх ComfyUI, раньше отдельный, не
встроенный в Studio инструмент) встроен в комплект как ещё один вариант
запуска ComfyUI, наравне с сырым интерфейсом самого ComfyUI.

## 1. Интеграция в лаунчер (`comfyui_studio/imagine/` как вариант запуска ComfyUI)

- Исходники Imagine перенесены в `comfyui_studio/imagine/` (backend +
  static), с адаптацией под запуск как части комплекта:
  - `backend/config_store.py` — пользовательские данные (config.json,
    uploads) теперь пишутся в `%APPDATA%\ComfyUIStudio\imagine\`, а не
    рядом с исходниками (иначе не работало бы в собранном
    PyInstaller-варианте и захламляло бы репозиторий).
  - `backend/workflow.py` — бандловый `workflow_template.json` перенесён
    в отдельную папку `imagine/assets/` (ассет только для чтения) с тем
    же приёмом на `sys._MEIPASS`, что и у `themes/theme_manager.py`.
  - `backend/main.py` — исправлен путь к статике (было
    `StaticFiles(directory="static")`, относительный путь, работавший
    только при запуске через `run.bat`, который сначала делал `cd` в
    папку инструмента; из Studio процесс стартует с `cwd` = корень
    проекта — путь резолвится абсолютно от расположения пакета).
  - `comfyui_studio/imagine/__main__.py` — новая точка входа
    `python -m comfyui_studio.imagine`, принимает `--host --port
    --comfy-host --comfy-port --dev`.
- `launcher/core/imagine_process.py` — управление процессом Imagine
  (`ImagineProcess`), по образцу `ComfyProcess`: находит собранный exe
  либо запускает из исходников, `taskkill /F /T` при остановке.
- `launcher/ui/widgets/launch_watcher.py` — добавлен
  `ImagineLaunchWatcher`, опрашивает готовность Imagine по HTTP (после
  того как `LaunchWatcher` уже подтвердил готовность ComfyUI).
- `launcher/ui/settings/comfyui_page.py` — новый раздел «Интерфейс»:
  переключатель ComfyUI / Imagine, порт Imagine, тумблер дев-режима.
- `launcher/ui/launcher_window.py` — при выборе Imagine лаунчер сначала
  поднимает ComfyUI как раньше, затем запускает Imagine, направленный
  на уже запущенный ComfyUI (`127.0.0.1:<port>`), и показывает во
  встроенном браузере уже интерфейс Imagine. Остановка/отмена/закрытие
  окна останавливают оба процесса.
- `comfyui_studio/i18n.py` — переводы всех новых строк лаунчера (RU/EN).
- `pyproject.toml` — добавлен extras `imagine` (fastapi, uvicorn,
  pydantic, python-multipart) и package-data для статики/ассетов
  Imagine.

Дев-режим Imagine **осознанно не имеет переключателя в самом
веб-интерфейсе** (это решение самого инструмента, см. `require_dev_mode()`
в `backend/main.py`) — тумблер добавлен только в настройках лаунчера, и
именно оттуда передаётся Imagine флагом `--dev` при запуске.

## 2. Темы (`static/css/themes.css`)

Добавлены палитры всех 6 тем комплекта (Dark, Light, Nord, Catppuccin
Mocha, Dracula, GitHub Dark), переведённые из `.qss`-файлов в CSS custom
properties поверх `[data-theme="..."]`. Значение `data-theme` — то же
название темы, что хранит `%APPDATA%\ComfyUIStudio\theme.json`
(`shared_theme.py`), без отдельного маппинга имён. `style.css` был уже
полностью на переменных (`--bg`, `--accent` и т.д.) — потребовалось
только вынести 3 места с захардкоженным цветом в переменную
`--bg-raised` и подключить `themes.css`.

Переключатель темы — выпадающий список в топбаре (`#themeSelect`),
подключён в `app.js` (`wireLanguageAndThemeControls`).

## 3. Локализация (`static/js/i18n.js`)

Словарь переводов по образцу `comfyui_studio/i18n.py` — русский
исходный текст как ключ, английский перевод как значение. Все статичные
строки разметки размечены атрибутами `data-i18n`/`data-i18n-placeholder`/
`data-i18n-title` (66 меток), все динамически генерируемые в `app.js`
строки обёрнуты в `t('ключ', {параметры})` (43 места вызова). Оба набора
сверены со словарём — непереведённых ключей не осталось.

Переключатель — кнопка-тумблер RU/EN в топбаре (`#langToggle`).

## 4. Синхронизация темы/языка со Studio

`backend/main.py`: `GET/PUT /api/ui-prefs` — читает и пишет те же
`%APPDATA%\ComfyUIStudio\theme.json`/`language.json`, что и остальные
части комплекта (`shared_theme.py`/`shared_language.py`). При загрузке
страницы (`I18N.init()`) сверяется с этим эндпоинтом один раз (без
файлового watcher — веб-странице он не нужен) и, если тема/язык в
Studio отличаются от того, что было в `localStorage`, применяет их.
Если Imagine запущен отдельно от Studio (без пакета `comfyui_studio` в
окружении), эндпоинт просто отдаёт `{"theme": null, "language": null}` —
переключатели остаются чисто локальными (`localStorage`).

## Не сделано / стоит проверить

- Собственный `backend/launcher.py` Imagine (самостоятельный запуск
  ComfyUI) оставлен как есть для автономного использования вне Studio —
  внутри Studio не используется (Studio передаёт готовый host/port
  через `--comfy-host/--comfy-port`).
- Реальный прогон (venv с `pip install .[imagine]`, живой ComfyUI) не
  выполнялся — только статическая проверка (`py_compile`, `node --check`,
  сверка ключей словаря, сверка id-элементов разметки). Стоит один раз
  прогнать вручную перед релизом.

## 29.08 — исправление: "Imagine не запустился" (код выхода 1, без подробностей)

Причина: `ImagineProcess.start()` отправлял stdout/stderr дочернего
процесса в `DEVNULL` — при падении (например ImportError из-за
неустановленных `fastapi`/`uvicorn`/`pydantic`/`python-multipart` в том
venv, из которого запущен ComfyUIStudio — extras `imagine` из
`pyproject.toml` не устанавливаются автоматически, их нужно поставить
отдельно) в лог попадал только голый код выхода, без единой подсказки.

Исправлено:
- `ImagineProcess` теперь перехватывает stdout+stderr процесса и, если
  тот завершился не с кодом 0, пишет последние ~4000 символов вывода
  (обычно это и есть traceback) в лог лаунчера (`APP_LOG_PATH`).
- Добавлена предварительная проверка зависимостей ДО запуска процесса
  (`_missing_imagine_dependencies()` в `imagine_process.py`) — если
  `fastapi`/`uvicorn`/`pydantic`/`python-multipart` не найдены в том же
  интерпретаторе, что запускает лаунчер, попытка запуска Imagine сразу
  завершается понятной ошибкой с командой для установки
  (`pip install .[imagine]`), вместо непонятного кода 1.
- Сообщение о раннем завершении процесса (`ImagineLaunchWatcher`)
  теперь указывает путь к лог-файлу с подробностями.

## 29.08 (продолжение) — Imagine рендерился, но был сломан: `t is not defined`

После того как Imagine стал открываться, обнаружились ещё четыре
проблемы, все — из одного источника.

**Причина:** `app.js` вызывает переводы как глобальную функцию
`t(...)` (43 места), а `i18n.js` определял `t` только внутри своего
замыкания и никогда не выставлял её наружу как `window.t`. Каждый
вызов бросал `ReferenceError`, обрывая текущую функцию на середине —
включая `init()`, из-за чего `wireStaticHandlers()` (вешает обработчик
клика на кнопку дев-режима) могла вообще не выполниться, и
`refreshComfyStatus()`, которая падала до записи текста в статус-бар
(отсюда — вечное "checking ComfyUI…", хотя связь с ComfyUI была в
порядке). Исправлено: `window.t = t;` в конце `i18n.js`.

Заодно, по замечанию, что тема/язык уже настраиваются централизованно
в основных настройках Studio: убраны переключатель темы (`<select>`) и
кнопка языка (RU/EN) из шапки Imagine (`index.html`, `app.js`) —
Imagine теперь молча следует за `/api/ui-prefs`, опрашивая раз в 5
секунд (а не только при загрузке), вместо того чтобы предлагать
собственный, дублирующий переключатель.

И исправлена сама кнопка дев-режима — на ней был `data-i18n-title`
(для тултипа), но не было `data-i18n` для текста самой кнопки, поэтому
надпись "⚙ дев-режим" не переводилась на английский.

## 29.08 (продолжение) — сборка: Imagine требовал отдельный exe

После сборки (`build_exe.bat`) переключение на интерфейс Imagine падало —
`resolve_imagine_launch()` искал отдельно собранный
`tools/imagine/dist/Imagine/Imagine.exe`, которого build_exe.bat никогда
не собирал (весь комплект собирается ОДНИМ exe, см. main.py и шапку
build_exe.bat).

Исправлено тем же приёмом, что уже используется для подпроцесса-
воркера эмбеддингов PromptVault (`comfyui_studio/promptvault/core/
embedding_ipc.py`, `WORKER_CLI_FLAG`): в frozen-сборке `sys.executable`
— это сам собранный `ComfyUIStudio.exe` (отдельного `python.exe` рядом
нет), поэтому вместо поиска стороннего exe лаунчер запускает САМ СЕБЯ
подпроцессом со скрытым флагом `IMAGINE_CLI_FLAG`
(`comfyui_studio/imagine/__main__.py`) — `main.py` ловит его в самом
начале, до `QApplication` и любых Qt-импортов, и вызывает
`comfyui_studio.imagine.__main__.main()` вместо обычного GUI-запуска.
Один и тот же exe в итоге умеет быть и GUI, и Imagine-подпроцессом —
отдельного `.spec`/сборки для Imagine не нужно.

Что изменилось:
- `main.py` — добавлена диспетчеризация `IMAGINE_CLI_FLAG` (по образцу
  уже существующей для `WORKER_CLI_FLAG`).
- `launcher/core/imagine_process.py` — `resolve_imagine_launch()`
  полностью переписан: убран поиск стороннего exe, при `sys.frozen`
  запускает `[sys.executable, IMAGINE_CLI_FLAG, ...]`, иначе как раньше
  `[sys.executable, "-m", "comfyui_studio.imagine", ...]`.
- `build_exe.bat` — `pip install .[imagine]` добавлен в ОБА профиля
  (core и full) — раньше extras `imagine` нужно было ставить вручную
  после сборки.
- `ComfyUIStudio-core.spec` / `ComfyUIStudio-full.spec` — добавлены
  `datas` для `comfyui_studio/imagine/static` и `.../assets` (чистая
  статика — .html/.css/.js/.json, PyInstaller не подхватывает такое
  сам) и `collect_all()` для `fastapi`/`starlette`/`uvicorn`/`multipart`
  (у них есть лениво импортируемые субмодули, которые обычный
  AST-анализ PyInstaller иногда не находит — тот же приём, что уже
  использовался для `sentence_transformers`/`transformers`/`tokenizers`
  в full-профиле).

Проверено: `python main.py --imagine-subprocess --host ... --comfy-host
...` действительно поднимает uvicorn напрямую, минуя Qt/QApplication —
именно так, как будет вызывать себя собранный exe.

## 29.08 (продолжение) — убрана настройка host/port ComfyUI в самом Imagine

По тому же принципу, что и с темой/языком: Studio передаёт host/port
ComfyUI Imagine при КАЖДОМ запуске (см. `_seed_comfy_target_from_env()`
в `backend/main.py`) — любое значение, вручную сохранённое через
собственную вкладку "Подключение" дев-режима Imagine, всё равно
перезаписывалось бы при следующем запуске из Studio. Поля `Host`/`Port`
убраны из этой вкладки (`index.html`, `app.js`) — остались только путь
к `.bat` и папка LoRA, которые Studio не знает и не подставляет.
Бэкенд (`PUT /api/config`) не менялся — `persistConfig()` в `app.js`
по-прежнему отправляет весь `state.config`, так что `comfyui.host`/
`.port` просто сохраняются как есть (тем, что подставила Studio), а не
затираются пустыми значениями.

## 29.08 (продолжение) — build_exe.bat: "Непредвиденное появление: .."

Сборка (`build_exe.bat full`) падала сразу на шаге "[3/6] Зависимости"
с криптичной ошибкой `Непредвиденное появление: ..` без дальнейшего
вывода pip.

Причина — классическая ловушка cmd.exe: `::`-комментарии внутри
скобочного блока `if (...) else (...)` ломают парсер, если круглая
скобка открывается на одной строке комментария и закрывается на
другой. Ровно это произошло при добавлении блока про `pip install
.[imagine]` — один из добавленных комментариев переносил `(...)` на
две строки внутри `if /i "%PROFILE%"=="core" ( ... ) else ( ... )`.

Исправлено: весь поясняющий комментарий вынесен ЦЕЛИКОМ ПЕРЕД
`if`-блоком (там скобки в тексте комментария безопасны — блок ещё не
открыт), внутри самих веток `if`/`else` остались только команды
`pip install`, без единого комментария. Проверил остальной файл на
этот же паттерн скриптом — других мест с `::`-комментариями внутри
скобочных блоков не нашлось.

## 29.08 (продолжение) — скроллбар не менял цвет вместе с темой

Скроллбар всей страницы Imagine был темизирован только для одного
горизонтального ряда стилей (`.styletilegrid::-webkit-scrollbar`) —
вертикальный скроллбар окна оставался нативным цветом Chromium/
QtWebEngine и не реагировал на смену темы. Добавлено общее правило
`*::-webkit-scrollbar`/`-track`/`-thumb`/`-corner` на основе тех же
переменных темы (`--border`, `--border-hover`, `--bg`), плюс
`scrollbar-width`/`scrollbar-color` для полноты (Imagine рендерится в
Chromium, но на случай показа в другом движке). Точечное правило для
`.styletilegrid` не трогал — оно специфичнее общего и по-прежнему
переопределяет высоту (6px, под горизontальную полосу).

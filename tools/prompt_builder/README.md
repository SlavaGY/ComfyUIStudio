# Character / Prompt Builder Config Editor (Qt)

GUI-редактор на **PySide6/Qt** (как в присланном референсе PromptVault) для
двух файлов расширения `character_search_ui`:

- **`characters.json`** — плоская база персонажей: `ключ -> теги`
  (плюс опциональная привязанная LoRA и её сила).
- **`prompt_builder_config.json`** — блочный конструктор промпта:
  дерево «групп» (вложенные вкладки) и «блоков» (multi_select /
  single_select / free_text) с вариантами (options), у каждого варианта —
  теги и опционально список LoRA. У блоков можно задать `max_random`,
  `default`, `required` и т.д. Плюс отдельные редакторы для
  `quality_prefix`, `source` и `negative_presets` (+ `negative_default`).

Формат файлов и семантика полей взяты из реального кода расширения
(`utils/char_utils.py`, `utils/prompt_logic.py`, `prompt_builder_node.py`,
`character_node.py`) — проверено на реальных файлах.

## Запуск

Внутренние импорты этого инструмента теперь пакетные (`from prompt_builder.xxx
import ...`, см. `tools/prompt_builder/__init__.py`) — по тому же принципу,
что и `app.xxx` у PromptVault. Из-за этого запускать нужно как модуль пакета
из папки `tools/` (на уровень выше `prompt_builder/`), а не `python main.py`
изнутри самой папки инструмента:

```bash
cd ..            # из папки prompt_builder/ наверх, в tools/
pip install -r prompt_builder/requirements.txt
python -m prompt_builder.main
```

(Как часть сборки всего комплекта ComfyUI Studio инструмент подключается
обычным `from prompt_builder.main import create_window` в корневом
`main.py` — см. его комментарии.)

## Память между запусками

Через `QSettings` (тот же файл настроек, что и для темы) запоминается:
- **Тема** — открывается в той же, что была выбрана в прошлый раз.
- **Папка** — та, что была открыта последней (через «Открыть папку
  расширения...» или через любой из диалогов «Открыть файл...»/«Сохранить
  как...»). При следующем запуске:
  - диалоги открытия/сохранения стартуют в этой же папке;
  - если в ней всё ещё лежат `characters.json` и/или
    `prompt_builder_config.json`, оба тихо подгружаются автоматически —
    можно просто открыть программу и продолжить редактирование без
    ручного «Открыть папку» каждый раз. Если папку удалили/переместили,
    ничего не сломается — просто ничего не подгрузится и не будет
    всплывающих ошибок.

## Темы

Темы — это те же `.qss`, что ты прислал (`themes/*.qss`): **Dark, Light,
Nord, Catppuccin Mocha, Dracula, GitHub Dark**. Переключаются в меню
**Вид → Тема**. Применяются через `ThemeManager` (`theme_manager.py`),
построенный по образцу твоего `themes/theme_manager.py` — целиком через
`QApplication.setStyleSheet()`, без единого обращения к нативному
заголовку окна (в отличие от прошлой Tkinter-версии — здесь никакого
DWM-хака нет, как ты и просил).

Присланные `.qss` не описывают часть виджетов, которых в PromptVault не
было (дерево блоков — `QTreeWidget`, вкладки — `QTabWidget`, таблицы
LoRA/пресетов — `QTableWidget`, `QGroupBox`, `QSpinBox`, меню, статус-бар).
Для них в `theme_manager.py` есть небольшой «довесок» к стилю, собранный
из той же палитры (см. `EXTRA_PALETTE` — значения сверены с `.qss`
построчно), так что цвета остаются едиными по всему приложению.

Выбор темы запоминается через `QSettings` (как и было в референсе) —
следующий запуск откроется в той же теме.

## Файлы проекта

- `main.py` — точка входа, `QMainWindow`, меню, статус-бар
- `theme_manager.py` — загрузка/применение `.qss`-тем + `QSettings`
- `themes/*.qss` — сами темы (без изменений, как в присланном архиве)
- `characters_tab.py` — вкладка «Персонажи»
- `promptbuilder_tab.py` — вкладка «Конструктор промпта» (дерево блоков +
  пресеты + негативы), включает миграцию старого формата LoRA
- `logic.py` — вся логика без привязки к GUI (валидация тегов, разбор
  LoRA, поиск/перенос устаревшего формата) — используется обеими вкладками
- `json_store.py` — загрузка/сохранение JSON с бэкапами (без изменений
  логики — она не зависела от GUI-фреймворка)
- `assets/app_icon.png` (+ `.ico`) — иконка окна/панели задач

## Дерево блоков — важная деталь реализации

PySide6 не сохраняет identity питоновских `dict`, если положить его через
`QTreeWidgetItem.setData(..., Qt.UserRole, словарь)` — Qt отдаёт **копию**
при каждом чтении `.data()`, а не ту же ссылку. Из-за этого прямые правки
узла через выделенный элемент дерева никогда не долетали бы до реальных
данных. Поэтому вместо самого словаря в дерево кладётся целочисленный
ключ, а сами словари живут в обычном питоновском реестре
(`self._node_registry`) — так мутации и сравнение по ссылке работают
корректно. Если будешь добавлять новые поля в дерево — используй
`self._item_info(item)` вместо `item.data(0, NODE_ROLE)` напрямую.

## Миграция старого формата LoRA

Как и в прошлой версии: при открытии `prompt_builder_config.json`
редактор сам ищет варианты со старым форматом (`"lora"`/`"lora_strength"`)
и предлагает перенести их на `"loras": [...]`. Кнопка
**«⇪ Старые LoRA»** на панели инструментов дерева блоков — та же проверка
вручную в любой момент.

## Иконка

`assets/app_icon.png` уже подключена в `main.py` через `setWindowIcon()`.
Нарисована программно (`assets/generate_icon.py`, на Pillow), без внешних
изображений — если нужно перерисовать другим цветом, там же и правится.

## Сборка в один .exe (Windows)

Через **PyInstaller**. Собирать нужно на Windows (PyInstaller не умеет
кросс-компилировать — .exe получится только если запускать сборку прямо
на Windows; из-под Linux/WSL получится Linux-бинарник, не .exe).

1. Установи Python 3.10+ с [python.org](https://www.python.org/downloads/)
   (при установке отметь галку **Add python.exe to PATH**).
2. Открой папку проекта в командной строке (`cmd` или PowerShell) и создай
   виртуальное окружение (не обязательно, но чище):
   ```bat
   python -m venv venv
   venv\Scripts\activate
   ```
3. Поставь зависимости и PyInstaller:
   ```bat
   pip install -r requirements.txt
   pip install pyinstaller
   ```
4. Собери по готовому спеку (`build.spec` уже в проекте — в нём прописаны
   темы, иконка и настройка «без консоли»):
   ```bat
   pyinstaller build.spec --noconfirm
   ```
   Либо просто запусти `build_windows.bat` — он сделает шаги 3–4 сам.
5. Готовый файл: **`dist\PromptConfigEditor.exe`** — один файл, ничего
   рядом класть не нужно (темы и иконка уже упакованы внутрь). Можно
   скопировать его куда угодно и раздавать отдельно от исходников.

Первый запуск .exe будет на пару секунд дольше обычного — PyInstaller в
режиме one-file распаковывает всё во временную папку при каждом старте,
это нормально.

Если конкретно нужен .exe без пересборки на Windows каждый раз при
изменении кода — держи `build.spec` как есть и просто перезапускай
`pyinstaller build.spec --noconfirm` после правок.

### Проверено

Я прогнал точно этот `build.spec` у себя (правда на Linux — получился
`.pkg`/ELF, а не `.exe`, кросс-сборка невозможна) и убедился, что: PyInstaller
корректно подхватывает все PySide6-зависимости без ручных hidden-imports,
упакованные `themes/*.qss` и `assets/app_icon.png` находятся во время
выполнения (код уже учитывает `sys._MEIPASS` — правки в `theme_manager.py`
и `main.py`), и собранный бинарник запускается из полностью
изолированной папки, где никаких `themes/`/`assets/` рядом нет. На
Windows с тем же `build.spec` разница будет только в том, что PyInstaller
на этот раз возьмёт `assets/app_icon.ico` и результатом будет `.exe`.

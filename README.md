# ComfyUI Studio (PySide6 / Qt)

Единый комплект из трёх инструментов, поставляемых в одном архиве и
работающих **в одном процессе** (один `main.py` в корне, один
`QApplication` на всех). Актуальная структура репозитория (после
этапов 1–5 дорожной карты рефакторинга — см.
`ComfyUIStudio_Refactoring_Roadmap.md`):

```
ComfyUIStudio/
├── main.py                        ← ЕДИНАЯ точка входа монолита (запускайте её)
├── pyproject.toml                 ← зависимости (base/[promptvault]/[dev]) + конфигурация
│                                     pytest/ruff/mypy — единая точка правды
├── requirements.txt                полный комплект зависимостей (альтернатива pyproject.toml,
│                                     пока не объединена с ним в один источник)
├── ComfyUIStudio-core.spec,       ← профили сборки PyInstaller (см. "Сборка в один exe")
│   ComfyUIStudio-full.spec
├── build_exe.bat                   одна сборка/один venv на весь комплект (core|full)
├── assets/                         icon.ico/icon.png лаунчера
├── comfyui_studio/                 общее пространство имён комплекта
│   ├── i18n.py, shared_theme.py, shared_language.py   ← общие на весь комплект
│   ├── themes/                     6 .qss тем + theme_manager.py
│   ├── launcher/                   ComfyUI Launcher (core/ui/integration)
│   ├── prompt_builder/             Character / Prompt Builder Config Editor
│   └── promptvault/                PromptVault
└── tools/                          ЛЕГАСИ: только служебные файлы сборки
    ├── prompt_builder/              отдельных standalone-exe (build_windows.bat/build.spec,
    └── promptvault/                 build.bat/PromptVault.spec) + tools/promptvault/tests/ —
                                      исходники самих инструментов здесь больше не лежат,
                                      см. предупреждение в конце этого README
```

Лаунчер (`comfyui_studio/launcher/`) — главное окно комплекта: запускает
ComfyUI в своей вкладке (см. ниже), а в настройках (единое дерево
настроек, см. `comfyui_studio/launcher/ui/settings/`) есть раздел
**«Другие инструменты»** с кнопкой «Запустить» для каждого из двух
других инструментов. У каждого инструмента — своё отдельное окно
(`QMainWindow`), но это окно **того же процесса**, а не отдельный
exe/подпроцесс: кнопка «Запустить» вызывает `create_window()`
соответствующего инструмента и просто показывает готовое окно (см.
`register_in_process_app()` в
`comfyui_studio/launcher/integration/tool_registry.py` и разводку в
корневом `main.py`). Повторное нажатие «Запустить» не плодит второе
окно — уже открытое просто поднимается на передний план.

До объединения (до этапа 1 дорожной карты) каждый инструмент был
полностью независимым процессом, и лаунчер запускал два других через
`subprocess.Popen`, подыскивая собранный `.exe` или исходники `main.py`
рядом с собой. Этот механизм (`launch_external_app()`/
`resolve_external_launch()` в
`comfyui_studio/launcher/core/comfy_process.py`) **оставлен как
запасной вариант**: если вы запустите окно лаунчера отдельно, напрямую
(в обход монолитного `main.py`), кнопки «Запустить» по-прежнему
попробуют найти и открыть `comfyui_studio.prompt_builder`/
`comfyui_studio.promptvault` отдельным процессом (`python -m
comfyui_studio.prompt_builder`/`.promptvault`) или собранный рядом
`.exe`. Но обычный сценарий использования теперь один: `python main.py`
(или собранный `ComfyUIStudio.exe`, см. ниже) — и всё открывается в
одном процессе.

### Общая тема для всех трёх инструментов

Тема оформления (Dark, Light, Nord, Catppuccin Mocha, Dracula, GitHub
Dark) — общая на весь комплект: `comfyui_studio/shared_theme.py` хранит
её в `%APPDATA%\ComfyUIStudio\theme.json`. Раньше (до объединения в
один процесс) синхронизация между инструментами шла только через
`QFileSystemWatcher` за этим файлом (три процесса, следящих за одним
файлом на диске); теперь, в одном процессе, `comfyui_studio/
shared_theme.py`/`shared_language.py` — буквально общий на все три
инструмента модуль в памяти, и все три инструмента (Launcher, Prompt
Builder, PromptVault) импортируют его напрямую из общего пакета
`comfyui_studio` — отдельных копий этих модулей внутри `prompt_builder/`
и `promptvault/` больше нет (были и дублировали друг друга байт-в-байт
до этапа 5 дорожной карты рефакторинга, см. "Удалить дубли shared_*").
`QFileSystemWatcher`-слежение при этом никуда не делось — оно по-прежнему
нужно на случай запуска инструментов отдельными процессами (см. раздел
про запасной вариант выше) и просто сосуществует с общим объектом в
памяти в монолитном режиме. Смена темы в любом уже открытом окне
применяется сразу и во всех остальных.

### Общий язык интерфейса (RU/EN) и единое дерево настроек

По тому же принципу — `comfyui_studio/shared_language.py`,
`%APPDATA%\ComfyUIStudio\language.json` — общий язык интерфейса.
Переключатель языка есть только в лаунчере (General → Language в
едином дереве настроек, см. ниже): Prompt Builder и PromptVault язык
сами не выбирают, только применяют то, что выбрано в лаунчере, и
подхватывают смену живьём, пока уже открыты.

Тема и язык настраиваются только в лаунчере — собственные переключатели
темы/языка убраны из Prompt Builder (меню «Вид → Тема») и из PromptVault
(группа "Appearance" в его окне настроек, вместо неё — подсказка, где
искать эти настройки). С этапа 4 дорожной карты рефакторинга в лаунчере
есть **единое дерево настроек** (`QTreeWidget`/`QStackedWidget`,
`comfyui_studio/launcher/ui/settings/app_settings_dialog.py`, открывается
кнопкой «Настройки...» с домашнего экрана лаунчера) с разделами General
(язык/тема/автозапуск/обновления), ComfyUI (папка установки/порт/
скрипт/аргументы/переменные окружения — бывший отдельный
`LaunchArgsDialog`), Prompt Builder (папка расширения, папка LoRA,
число резервных копий), PromptVault (расположение и резервное
копирование базы данных + кнопка-мост в собственное окно настроек
PromptVault для специфичных для него параметров — поиск,
производительность, хранилище, горячие клавиши) и Advanced (уровень
логирования, диагностика, сброс настроек лаунчера, перезапуск/выход из
всего комплекта). Настройки, специфичные только для PromptVault
остаются в его собственном окне настроек, открываемом из раздела
PromptVault единого дерева, — переносить их в само дерево лаунчера не
планируется (см. дорожную карту, этап 4, "По факту реализации").

Охват перевода на английский сознательно ограничен основным "хромом"
интерфейса — то, что человек видит регулярно (меню, кнопки, заголовки,
подсказки), а не вообще каждая строка в приложении:

- **Лаунчер** (`comfyui_studio/i18n.py`): экран настроек, единое дерево
  настроек, панель лога, окно браузера ComfyUI, меню трея.
- **Prompt Builder** (`comfyui_studio/prompt_builder/pb_i18n.py`): меню,
  заголовки вкладок, диалог "О программе", стартовое сообщение в строке
  статуса.
- **PromptVault**: у него уже был полноценный QTranslator/.ts/.qm — см.
  `comfyui_studio/promptvault/i18n.py` и `tools/promptvault/CONTRIBUTING.md`.

Живая телеметрия (CPU/RAM/GPU-чипы, подсказка трея с очередью), поля
внутри вкладок "Персонажи"/"Конструктор промпта" в Prompt Builder
и сообщения в лог-панели лаунчера пока остаются на русском — их
перевод стоит дороже, чем перевод основных элементов управления, и
отложен на потом.

## Возможности

- Автопоиск всех `run_*.bat` в корне папки и в `advanced\`.
- Запуск ComfyUI не переключает экран — индикатор прогресса и статус
  появляются прямо внизу экрана настроек, поверх уже видимой панели
  «Лог последнего запуска», так что весь процесс старта (включая
  загрузку моделей/кастомных нод) виден live, без отдельного
  «экрана ожидания». Кнопка «Отмена» рядом с прогрессом останавливает
  запуск, если он застрял. На экран браузера переключаемся только
  когда сервер реально ответил на `/`; если процесс упал раньше
  времени или не поднялся за 3 минуты — сразу видно код выхода прямо
  тут же, экран не переключается.
- Встроенный просмотр ComfyUI без адресной строки и вкладок:
  - клик по ссылке на другой домен (документация, GitHub) уходит в
    обычный системный браузер;
  - попытка открыть «новое окно» (`window.open`, `target=_blank`,
    Ctrl+клик) не создаёт нового окна;
  - системное контекстное меню отключено.
- **Значок приложения и значок в трее** (сгенерированный `assets/icon.ico`,
  узел-граф в тон интерфейсу ComfyUI).
- **Логирование через модуль `logging`** — все события самого лаунчера
  (запуск/остановка, ошибки, автосохранение) пишутся в
  `%APPDATA%\ComfyUILauncher\launcher.log` с ротацией (3 файла по 2 МБ).
  Вывод самого ComfyUI (его печать в консоль) идёт отдельно —
  см. ниже.
- **Автосохранение настроек** — путь, скрипт, порт и галочка
  disable-auto-launch сохраняются в `config.json` через ~0.4 сек после
  любого изменения поля, без отдельной кнопки «Сохранить».
- **Обработка ошибок запуска прямо в интерфейсе** — вывод процесса
  ComfyUI (stdout/stderr) построчно перехватывается и показывается в
  панели «Лог последнего запуска» на экране настроек в реальном
  времени, плюс пишется в `comfyui_last_run.log`. Если сервер не
  поднялся или упал — вы сразу видите живой лог, не открывая
  сторонних окон. Отдельного окна консоли больше нет.
- **Мониторинг ресурсов, теперь цветной** — CPU, RAM, загрузка и
  температура GPU (через `psutil` и `pynvml`/NVML — работает с
  NVIDIA-картами; на системах без NVIDIA GPU эти поля просто
  показывают «нет данных»), плюс очередь генераций ComfyUI
  (`выполняется/ожидает`, из `/queue`). Данные обновляются раз в
  2 секунды и видны:
  - цветными "чипами" (зелёный/жёлтый/красный по уровню нагрузки —
    ниже 60% зелёный, 60–85% жёлтый, выше — красный; для температуры
    GPU пороги 70°C/84°C) в верхней панели окна браузера **и** на
    экране настроек — цвет чипа сразу показывает, где узкое место, а
    не сливается с фоном темы;
  - компактной всплывающей подсказкой трея (см. ниже про её длину).
- **Тема оформления, общая на весь комплект** — переключатель в едином
  дереве настроек (General → Theme; Dark, Light, Nord, Catppuccin
  Mocha, Dracula, GitHub Dark), применяется сразу и синхронизируется с
  двумя другими приложениями комплекта живьём, пока они открыты (см.
  раздел про `shared_theme.py` выше). QSS-файлы тем лежат в
  `comfyui_studio/themes/*.qss` — можно править цвета или добавить свою
  тему, просто прописав её в `AVAILABLE_THEMES` в `theme_manager.py`
  (свой `theme_manager.py` — у каждого из трёх инструментов, все три
  читают тот же общий `comfyui_studio/shared_theme.py` для
  синхронизации).
  Цветные чипы ресурсов при этом остаются цветными на любой теме — их
  цвет всегда показывает уровень нагрузки, а не берётся из темы. Верхняя
  панель окна браузера и панель лога запуска раньше были захардкожены
  под тёмный вид независимо от темы — теперь тоже красятся выбранной
  темой.
- **Раздельные кнопки «Настройки» и «Остановить»** — раньше обе
  останавливали сервер. Теперь:
  - «← Настройки» просто открывает экран настроек, ComfyUI продолжает
    работать в фоне; на экране настроек появляется зелёная плашка
    «ComfyUI уже запущен» с кнопками «Открыть ComfyUI» (вернуться без
    перезапуска) и «Остановить»;
  - «⏹ Остановить» действительно останавливает процесс (со всем
    деревом, `taskkill /F /T`) и возвращает к обычному экрану
    настроек с разблокированными полями.
- Закрытие окна (крестик) сворачивает приложение в трей, а не
  завершает его — ComfyUI продолжает работать. Полностью выйти можно
  через пункт «Выход» в меню трея (если ComfyUI ещё запущен —
  спросит подтверждение и остановит его).

## Про синхронизацию темы с интерфейсом ComfyUI

Галочка «Синхронизировать тему ComfyUI с темой приложения» на экране
настроек (по умолчанию выключена) переключает **встроенную** палитру
самого ComfyUI на ближайший аналог выбранной темы Qt — правится файл
`ComfyUI/user/default/comfy.settings.json` (ключ `Comfy.ColorPalette`),
другие настройки в этом файле не трогаются. Делается это перед каждым
запуском сервера — после старта ComfyUI сам владеет этим файлом, так
что на лету, пока сервер уже работает, переключить тему таким способом
нельзя (только при следующем запуске).

Соответствие:

| Тема лаунчера | Палитра ComfyUI |
|---|---|
| Dark | `dark` |
| Light | `light` |
| Nord | `nord` |
| GitHub Dark | `github` |
| Catppuccin Mocha | `dark` (точного аналога нет — ближайшая тёмная база) |
| Dracula | `dark` (точного аналога нет — ближайшая тёмная база) |

Это не полноценная перекраска один-в-один — у ComfyUI своя система
цветов для узлов/канваса, отдельная от QSS-тем приложения, и полноценная
инъекция произвольного CSS туда была бы гораздо более хрупким решением
(легко ломается при обновлениях фронтенда ComfyUI — вы уже видели тому
пример в виде deprecation warnings про устаревшие JS API). Переключение
встроенной палитры — официально поддерживаемый и самый стабильный
способ.

## Про обрезанную строку с очередью в подсказке трея

Windows обрезает текст всплывающей подсказки трея примерно на 128
символах без предупреждения — именно поэтому строка с очередью
обрывалась на середине числа. Подсказка переписана компактнее (без
заголовка, короче формулировки), плюс добавлена жёсткая подстраховка
по длине в коде (`format_stats_tooltip`) — теперь весь текст с запасом
укладывается в лимит.

## Про предупреждения `[DEPRECATION WARNING] ... /scripts/ui.js` и т.п.

Это сообщения самого фронтенда ComfyUI о том, что какое-то из
установленных расширений (custom nodes) использует устаревший JS API
— они печатаются самим ComfyUI при старте, лаунчер их никак не
провоцирует и не может «починить». Они не блокируют работу. Теперь их
видно прямо в панели лога на экране настроек — оттуда удобно
скопировать текст и посмотреть, какое расширение ругается, и при
желании обновить/отключить его в ComfyUI Manager. Если вас не
интересует, какие расширения устарели — эти строки можно просто
игнорировать, на работу самого ComfyUI они не влияют.

## Установка и запуск (из исходников)

Нужен обычный системный Python 3.11+ (НЕ `python_embeded` из состава
ComfyUI portable — тот только для самого ComfyUI). Два эквивалентных
способа поставить зависимости:

```
pip install -r requirements.txt
python main.py
```

либо через `pyproject.toml` (обязательные зависимости + опциональные
группы `promptvault` и `dev`, см. ниже):

```
pip install .
python main.py
```

`pyproject.toml` разбивает зависимости на обязательные и опциональную
группу `promptvault` (torch/sentence-transformers — семантический поиск
в PromptVault, самые тяжёлые зависимости всего комплекта): `pip
install .` ставит комплект БЕЗ семантического поиска (PromptVault при
этом всё равно открывается и работает — обычный текстовый поиск,
фильтры, галерея; в его настройках чекбокс «Enable semantic search»
просто задизейблен с пояснением), `pip install .[promptvault]` — с ним,
`pip install .[dev]` — плюс pytest/ruff/mypy для разработки (см.
`tools/promptvault/CONTRIBUTING.md` — конфигурация этих инструментов
живёт в этом же корневом `pyproject.toml`, слита туда из отдельного
`tools/promptvault/pyproject.toml` на этапе 5 дорожной карты
рефакторинга). `requirements.txt` пока сосуществует с `pyproject.toml`
как отдельный источник того же набора зависимостей (для тех, кто не
хочет ставить пакет через `pip install .`) — слияние их в один
источник правды в объём этапа 5 не входило и остаётся открытым пунктом.

`main.py` — единая точка входа монолита: поднимает один `QApplication`
и показывает окно лаунчера; Prompt Builder и PromptVault открываются из
него же (см. выше). Обычный сценарий — именно `python main.py`; запуск
окна лаунчера отдельно, в обход `main.py` (см. выше про запасной
вариант через subprocess), тоже возможен, но не является основным
способом использования комплекта.

`PySide6` уже включает Qt WebEngine и QtCharts (нужен для графиков в
PromptVault). `nvidia-ml-py` даёт метрики GPU только на системах с
NVIDIA-картой и установленными драйверами — на других система молча
покажет «нет данных» вместо GPU-метрик (это видно в `launcher.log` как
предупреждение при старте).

## Сборка в один exe

`build_exe.bat` в корне репозитория собирает **весь монолит одним
exe**: свой отдельный venv для сборки, one-folder (не `--onefile` —
PySide6 + QtWebEngine + (в full-профиле) torch + sentence-transformers
в сумме дают сотни МБ, распаковывать это заново при каждом запуске не
нужно), упаковка результата в `.zip` в конце.

Есть ДВА профиля сборки (каждый — свой `.spec`-файл,
`ComfyUIStudio-core.spec` / `ComfyUIStudio-full.spec`):

```
build_exe.bat core   :: без семантического поиска — без torch/sentence-transformers, заметно легче и быстрее собирается
build_exe.bat full   :: полный комплект, как было раньше (аргумент можно не указывать — full по умолчанию)
```

Результат — `dist\ComfyUIStudio\ComfyUIStudio.exe` и вся папка рядом
(плюс `dist\ComfyUIStudio-win64-core.zip` или `-full.zip` для
распространения — распаковывать нужно ВСЮ папку, не только `.exe`).
Запуск открывает окно лаунчера; кнопки «Запустить» на странице «Другие
инструменты» открывают Prompt Builder и PromptVault окнами этого же
процесса — отдельных exe для них внутри сборки нет и распространять их
отдельно не нужно.

**Про отдельные standalone-сборки каждого инструмента**
(`tools/prompt_builder/build_windows.bat`/`build.spec` и
`tools/promptvault/build.bat`/`PromptVault.spec`): исторически они
позволяли собрать один инструмент отдельно от остального комплекта.
После переноса исходников под общее пространство имён `comfyui_studio/`
(этап 2 дорожной карты рефакторинга) эти скрипты **не были обновлены**
— они по-прежнему ссылаются на старую раскладку (`app\main.py` для
PromptVault, аналогично для Prompt Builder), которой в репозитории
больше нет, и в текущем виде, по всей видимости, не соберут рабочий
exe. Если вам нужна именно отдельная standalone-сборка одного
инструмента — эти `.bat`/`.spec` нужно сначала привести в соответствие
с `comfyui_studio/prompt_builder/`/`comfyui_studio/promptvault/`
(по образцу того, как это уже сделано в `ComfyUIStudio-core.spec`/
`-full.spec` для монолита); эта работа не входит в объём этапов 0–5
дорожной карты рефакторинга и пока не выполнена.

## Файлы, которые лаунчер создаёт в `%APPDATA%\ComfyUILauncher\`

| Файл | Назначение |
|---|---|
| `config.json` | сохранённые настройки (автосохранение) |
| `launcher.log` | лог самого приложения (модуль `logging`, с ротацией) |
| `comfyui_last_run.log` | сырой вывод последнего запуска ComfyUI |
| `_launch_current.bat` | временная копия выбранного `.bat` с `--disable-auto-launch` |
| `webengine_profile\` | профиль Chromium (куки/локальные данные интерфейса ComfyUI) |

Кроме этого, в `%APPDATA%\ComfyUIStudio\` (общая на весь комплект,
отдельно от `%APPDATA%\ComfyUILauncher\`) лежат `theme.json` и
`language.json` — общие тема и язык всех трёх приложений (см. разделы
про них выше).

## Известные ограничения

- Тестировалось логически и через headless-смоук-тесты конструкции
  окна (нет Windows-машины под рукой для полного визуального прогона);
  перед первым «боевым» использованием стоит проверить, что WebEngine
  нормально стартует на вашей машине.
- GPU-метрики — только NVIDIA (через NVML). Для AMD/Intel температуру
  и загрузку получить без дополнительных вендор-специфичных библиотек
  не получится, в текущей версии эти поля просто пустые.
- Если ComfyUI слушает не `127.0.0.1`, а `0.0.0.0` с нестандартным
  портом — укажите порт вручную в настройках лаунчера.
- Кнопки «Запустить» в блоке «Другие инструменты» не проверяют, не
  запущено ли приложение уже — можно случайно открыть второй экземпляр
  (актуально только для запасного сценария запуска отдельными
  процессами — см. выше; в обычном монолитном режиме повторное
  нажатие поднимает уже открытое окно, а не плодит новое).
- Перевод на английский покрывает только основной "хром" интерфейса
  (см. раздел про язык выше) — часть текста (телеметрия, поля внутри
  вкладок Prompt Builder, сообщения в логах) всегда на русском.
- Единое дерево настроек пока частичное: General/ComfyUI/Prompt
  Builder/PromptVault (частично)/Advanced централизованы в лаунчере, но
  специфичные настройки PromptVault (горячие клавиши, поиск,
  производительность, хранилище) остаются в его собственном окне,
  открываемом мостом из раздела PromptVault — полный перенос в дерево
  лаунчера не планируется (см. дорожную карту, этап 4).
- `requirements.txt` и `pyproject.toml` в корне описывают один и тот же
  набор зависимостей двумя параллельными источниками — ещё не слиты в
  один (см. "Установка и запуск" выше).
- Standalone-сборки отдельных инструментов
  (`tools/prompt_builder/build_windows.bat`, `tools/promptvault/build.bat`)
  ссылаются на раскладку файлов до переноса под `comfyui_studio/` и,
  по всей видимости, не работают в текущем виде — см. предупреждение в
  разделе "Сборка в один exe" выше. Профили `ComfyUIStudio-core.spec`/
  `-full.spec` для монолитной сборки актуальны и обновляются вместе с
  остальным кодом.

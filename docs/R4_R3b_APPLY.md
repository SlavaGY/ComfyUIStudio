# R4 + R3b — как применить

Архив — **наложение** на корень репозитория (после R3). Удалять в git
ничего не нужно.

## R4 — блок Remote вынесен из `MainWindow`

Новое: `comfyui_studio/launcher/ui/remote_controller.py` —
`RemoteController` владеет `RemoteProcess`, опросом готовности
(300 мс × 20 попыток) и вызовами локального API (pairing, список, отзыв).
`MainWindow` создаёт его и соединяет с ним сигналы страницы настроек;
методы `_start_remote`, `_poll_remote_ready`, `_stop_remote`,
`_on_remote_*` и атрибуты `remote_process`, `_remote_ready_attempts` из
окна удалены (`launcher_window.py` стал на ~190 строк короче).

**Единственное намеренное изменение поведения:** `call_local_api`
(таймаут 3 с на вызов) выполняется в рабочем потоке, результат
возвращается в GUI-поток сигналом. Раньше недоступный Remote замораживал
окно; при отзыве нескольких устройств — на время каждого вызова подряд.
Попутно:
- ответ, пришедший после остановки/перезапуска Remote, отбрасывается;
- повторный клик по тому же действию, пока запрос не завершён,
  игнорируется;
- неожиданное исключение (например `TimeoutError` на чтении ответа) и
  ответ pairing без нужных полей теперь показываются текстом в окне, а не
  улетают из слота необработанными.

Не менялось: условия запуска (свежий `load_config()` с диска), тексты
сообщений, прерывание отзыва на первой ошибке, список устройств после
успешного отзыва. Опрос готовности `is_remote_available` (localhost,
таймаут 1 с) пока остаётся в GUI-потоке — его перенос идёт вместе с
остальными опросами в R6.

Тесты: `tests/launcher/test_remote_controller.py` (33). 22 из них —
перенесённые из `test_main_window_flow.py` Remote-тесты с теми же
ожиданиями (асинхронность скрыта синхронным `spawn`), плюс устаревшие
ответы, двойной клик и два теста на настоящих потоках (pytest-qt).
Из `test_main_window_flow.py` Remote-тесты удалены; остальное в нём не
менялось.

## R3b — оставшиеся `taskkill`

`managed_process.py` получил `terminate_pid_tree(pid, label)` (PID без
объекта Popen) и общий `_taskkill_tree`. На них переведены:
- `remote/comfy_launcher.py::stop_comfyui` → `terminate_process_tree`;
- `remote/process_by_port.py::kill_pid_tree` → `terminate_pid_tree`.

Тесты: `tests/remote/test_process_stop.py` (7).

**Сознательно не тронуто:** `imagine/backend/promptgen.py::_kill_tree`.
`taskkill` там — лишь запасной путь без psutil; основной путь (обход
дерева psutil, terminate → ожидание → kill, отчёт для лога) — другой
алгоритм, и подмена его на `taskkill` ухудшила бы остановку llama-server.

## Проверка

```
pytest
```

Ожидание на Windows: прежние 702 passed / 68 skipped, минус 22
перенесённых Remote-теста в старом месте, плюс 33 + 7 новых
(≈ 720 passed / 68 skipped; оценка, не гарантия).

Вручную:
1. Включить удалённый доступ → статус «запущен», LAN-адрес при доступе
   по сети.
2. «Получить код» / «Обновить список» / «Отозвать» при работающем Remote
   — как раньше.
3. Остановить Remote (выключить переключатель) и сразу нажать «Получить
   код» — сообщение «Remote не запущен», окно не подвисает.
4. Закрыть Studio — процесс Remote не остаётся в диспетчере задач.

1968 генераций, 1961 запись внутри основной папки ComfyUI output. База занимает

## Изменения по результатам замеров

- Страница сначала выбирается как узкий список ID с фильтрами, сортировкой,
  избранным и LIMIT/OFFSET. Тексты промптов загружаются только для выбранных ID.
  Порядок восстанавливается по этому списку. Большие тексты больше не попадают
  в временную сортировку предыдущих страниц.
- Добавлен покрывающий индекс `idx_generations_browse` по пути и полям
  фильтров/сортировки. EXPLAIN подтверждает COVERING INDEX при выборе обычной
  страницы, фильтре LoRA и чтении списка моделей. Индексы CFG и Steps позволяют
  строить гистограммы без обхода страниц таблицы с workflow/промптами.
  Три новых индекса на этом снимке занимают 372736 байт (364 КиБ).
  Они создаются автоматически при открытии существующей БД.
- Подсчёт без фильтров больше не присоединяет user_data.
- На Windows каталоги с минимум 128 известными JSON используют пакетные
  метаданные `os.scandir`, полученные FindFirstFile. Это быстрее отдельных
  stat для каждого файла на измеренной библиотеке. Маленькие неизменившиеся
  каталоги по-прежнему обходятся без перечисления содержимого.
- При перечислении метаданные DirEntry переиспользуются; обычные файлы
  не требуют отдельного resolve. Корень, каталоги (включая Windows junction)
  и символические ссылки разрешаются с сохранением канонических путей.
- Резервный опрос при простое меняет интервал 4 → 8 → 16 секунд. Событие
  файловой системы возвращает 4 секунды и debounce 250 мс; непрерывные события
  не перезапускают уже работающий быстрый таймер. Изменения, начальный результат
  и ошибка тоже возвращают быстрый режим. Одновременные сканирования исключены.

При длительном простое это примерно в 8,5 раза меньше суммарного времени
резервных проверок по измеренным медианам: проверка ускорилась в 2,1 раза,
а интервал вырос в 4 раза. Это расчёт для тихой папки, а не замер CPU всего
приложения. При пропущенных событиях watcher резервное обнаружение теперь
может занимать до 16 секунд. Полная сверка остаётся периодической, примерно
раз в 60–76 секунд с учётом адаптивного таймера.

## Проверки и воспроизведение

На реальной библиотеке сравнивались старые и новые результаты 105 страниц:
все режимы сортировки, пустой фильтр, модель, текстовый поиск, избранное и
рейтинг; смещения 0, 100 и 1800. Объекты Generation полностью совпали.
Регрессионные тесты дополнительно сравнивают узкую и широкую выборки на
повторяющихся ключах сортировки, отсутствующих user_data, LoRA без учёта
регистра, пустых и глубоких страницах. Проверены пакетная проверка Windows,
изменение размера при сохранённом mtime, рост/сброс интервала, поток событий,
смена папки и устаревшие результаты рабочих потоков.

Полный прогон PromptVault: **517 passed**. Финальный адресный прогон индекса,
синхронизации и выборки страниц после проверки непрерывных событий:
**63 passed**. Ruff, mypy (202 модуля) и `git diff --check` прошли.

Повторить замер можно из корня репозитория:

```powershell
python -m tools.benchmark_promptvault --source "$env:USERPROFILE\.promptvault\promptvault.db" --snapshot "tmp/promptvault-benchmark.sqlite3" --output "tmp/promptvault-metrics.json"
```

Для сравнения до/после следует использовать один снимок и одну папку.
Индексы увеличивают стоимость записи и размер БД; на этой библиотеке добавочный
размер невелик. Подстрочный поиск остаётся сканированием текстов; семантика
поиска сохранена. Глубокая страница всё ещё использует OFFSET, однако сортирует
метаданные, а не полные тексты: замеры не потребовали менять API пагинации.

# R7 — единое хранилище конфигурации (`ConfigStore`)

Архив — **наложение** на корень репозитория (после R6). Удалять в git
ничего не нужно.

## Что было не так

У конфигурации было несколько «владельцев»: `MainWindow.cfg`,
`SettingsPage.cfg`, `AppSettingsDialog.cfg` и копии на страницах. Диалог
автосохранял правки в свой снимок, остальные держали устаревшие — отсюда
обходные пути (запуск брал cfg «из диалога», Remote перечитывал
`config.json` с диска). Сами эти обходные пути давали гонку из-за
дебаунса автосохранения (400 мс):

- **Remote**: пользователь ввёл порт и сразу включил переключатель —
  `RemoteController.start()` читал с диска ещё старый конфиг.
  Воспроизведено на R6 на настоящем диалоге: форма 7999, Remote стартует
  на 7861. На R7: 7999.
- **«Запустить»** сразу после ввода порта/пути брал снимок диалога без
  отложенных правок.

## Что изменилось

Новое: `launcher/core/config_store.py` — `ConfigStore`:
- `cfg` — текущий снимок; каждое изменение создаёт **новый** dict
  (copy-on-write), поэтому снимок, взятый запуском ComfyUI, не меняется
  при последующих правках в настройках;
- `update(changes, force_save=False)` — поверхностное слияние (как
  прежнее `cfg.update(page.collect())`), запись и сигнал `changed` только
  при реальном изменении; `save()`, `reload()`, `reset()`.

Проводка:
- `MainWindow.config = ConfigStore()`; его получают `SettingsPage`,
  `AppSettingsDialog` и `RemoteController`. Атрибут `MainWindow.cfg`
  удалён.
- `AppSettingsDialog`: `cfg` теперь свойство (`config.cfg`); автосохранение
  идёт через `config.update(..., force_save=True)` (config.json пишется при
  каждом автосохранении, как раньше). Новый `flush()` сохраняет
  отложенные правки немедленно; он вызывается из `hideEvent`, перед
  сигналом включения Remote и перед запуском ComfyUI. После сброса
  настроек (Advanced) хранилище перечитывается с диска.
  Диалог по-прежнему принимает и обычный dict (создаёт своё хранилище).
- `SettingsPage._on_launch`: `flush()` → снимок `config.cfg` →
  `config.save()` → `launch_requested`. Сигнал не менялся.
- `RemoteController(config=...)`: берёт актуальный снимок из хранилища,
  без `config` (отдельное использование) читает диск, как в R4.
- `MainWindow`: всё, что описывает **запущенную** сессию (порт для
  браузера и «Настройки» из браузера, флаг синхронизации темы ComfyUI),
  читается из `launch_controller.cfg` — снимка на момент запуска; до
  первого запуска — из хранилища. Так остаётся прежняя семантика: правки
  в настройках во время работы ComfyUI на запущенную сессию не влияют.

## Поведение

Менялось только устранение двух гонок выше. Формат `config.json`,
`load_config()`, `save_config()`, `DEFAULT_CONFIG` не тронуты
(`test_config_load_save.py` из R0 без изменений).

Заметка для тех, кто будет читать код: `launch_requested = Signal(dict)`
доставляет получателю **копию** словаря (QVariantMap, ключи по алфавиту),
а не тот же объект — так было и раньше; это ещё одна причина, по которой
снимок запуска нельзя «случайно» изменить через хранилище.

## Что не сделано (сознательно)

- Типизированные секции (`cfg["remote"]["port"]` → объект) — это отдельный
  шаг, он затронул бы все страницы и `remote/*`. `ConfigStore` его не
  блокирует.
- Процессы Remote/Imagine читают `config.json` с диска при своём старте —
  это отдельные процессы, общего объекта у них нет.
- Страницы настроек (`General/ComfyUI/Advanced/Remote`) по-прежнему
  получают стартовый dict в конструктор; живое значение они берут из
  своих виджетов, а диалог подмешивает их через `collect()`.

## Тесты

- `tests/launcher/test_config_store.py` (22): ConfigStore (copy-on-write,
  запись только при изменении, `force_save`, `reload`, `reset` без
  алиасинга дефолтов), диалог + Remote + запуск на настоящих виджетах
  (включение Remote сразу после смены порта, «Запустить» сразу после ввода
  порта, `hideEvent`, снимок запуска не меняется правками после него).
  Две мутации (убрать `flush()` в сигнале Remote / в запуске) валят
  соответствующие тесты.
- `tests/launcher/test_main_window_flow.py`: harness больше не имеет
  `cfg`; тесты читают снимок сессии из `launch_controller.cfg`, а «живой»
  конфиг в harness нарочно отличается (порт 1111), чтобы тесты ловили
  чтение не оттуда.

```
pytest
```

Ожидание: на 22 теста больше, чем у вас после R6. Песочница (Linux):
493 passed в `tests/`, 373 passed в `tools/promptvault/tests`.

Вручную:
1. В «Настройки → Удалённый доступ» введите порт и сразу включите
   переключатель — Remote должен подняться на введённом порту.
2. Впишите путь к ComfyUI и сразу нажмите «Запустить».
3. Запустите ComfyUI, откройте «Настройки» из браузера, поменяйте порт —
   запущенный ComfyUI остаётся на прежнем (поле и так заблокировано).
4. «Дополнительно → Сбросить настройки» — после перезапуска Studio
   значения по умолчанию.

## Изменения

- **Список чатов LM Studio.** Поля `title` и `model` вынесены в колонки SQLite.
  Существующие базы автоматически заполняют их из сохранённых диалогов;
  исходный JSON и сообщения сохраняются. Выборка списка читает только
  `id/title/model/updated` из покрывающего индекса, без загрузки тел сообщений.
  Обработчик списка выполняется в пуле потоков FastAPI.
- **Потоковый ответ LM Studio.** Обновления объединяются с интервалом 50 мс.
  DOM сообщения, область ответа и раскрывающийся блок рассуждения сохраняются.
  Обновления только рассуждения не запускают Markdown/KaTeX повторно.
  Сохраняются выбор пользователя раскрыть/свернуть рассуждение, копирование
  актуального текста и условная автопрокрутка. При завершении/ошибке/остановке
  таймер снимается, оставшийся текст отображается.
- **Синхронизация PromptVault.** Первичная индексация, периодические проверки
  и обнаружение вложенных папок выполняются вне GUI, через отдельное соединение
  SQLite, которое закрывается в рабочем потоке. Сначала показываются уже
  проиндексированные данные, после сканирования обновляются список и фильтры.
  Одновременно выполняется одна операция; события файловой системы объединяются
  за 250 мс. Смена папки/остановка исключает доставку устаревших результатов.
  Тихое восстановление папки при запуске сохраняется. Синхронный программный
  API `GalleryManager.load_folder()` остаётся доступен.

## Второй этап: загрузки и HTTP-кэш

- Remote пересылает входящее тело через `request.stream()` в поток HTTPX.
  Промежуточного `request.body()` больше нет. Сохраняется Content-Length,
  если он известен; для остальных запросов HTTPX формирует chunked-передачу.
  Обратное давление upstream ограничивает чтение входящего запроса.
- Imagine копирует содержимое `UploadFile` блоками по 1 МиБ в рабочем потоке
  FastAPI. Большие multipart-файлы уже спулируются Starlette на диск;
  повторного чтения целиком в RAM больше нет. Готовый файл публикуется
  переименованием временного `.part`; ошибка копирования удаляет временный файл.
- Imagine, Imagine Pony и LM Studio используют общий `CachedStaticFiles`.
  Локальные ссылки на JS/CSS/изображения в HTML получают `?v=<SHA-256>`.
  Относительные пути сохраняются, включая общий `/common` за Remote-прокси.
  Хэши вычисляются в рабочем потоке и кэшируются с учётом размера и времён файла.
- Политика ответов:

  | Ответ | Cache-Control |
  |---|---|
  | HTML, API, пользовательские `/media`, ошибки | `no-store` |
  | Статика с совпадающим хэшем в URL | `private, max-age=31536000, immutable` |
  | Статика без хэша или с устаревшим хэшем | `private, no-cache, must-revalidate` |

  Файлы без хэша, включая шрифты из CSS, сохраняют условные запросы ETag/304.
  После изменения JS/CSS HTML получает новые ссылки даже без перезапуска сервиса.
- Персонализированный HTML Remote с токеном устройства всегда получает
  `no-store`. Валидаторы и Content-Encoding исходного HTML удаляются, поскольку
  прокси декодирует и изменяет тело. Заголовки кэша и Range для остальной статики
  проходят через прокси без изменения.
- Новый ASGI-middleware задаёт заголовки, не оборачивая и не буферизуя тела.

Новые тесты проверяют передачу блоков до чтения следующего, Content-Length
и chunked, отказ upstream в середине загрузки, ограниченные чтения UploadFile,
уборку временных файлов, смену версий ресурсов, относительные URL за прокси,
ETag/304, HEAD, Range и отсутствие кэша для токенов/API/пользовательских файлов.

В изолированном замере копирования файла 64 МиБ (`tracemalloc`, создание
исходного файла исключено) пик выделений Python снизился с 64,01 до 2,02 МиБ.
Это замер самой операции копирования, без multipart-парсера, сети и общей RAM
процесса; длительность передачи по сети не измерялась.

# RVC-1 + RVC-2 — Ultimate RVC в Studio

Файлы в патче полные (не диффы): кладутся поверх проекта, в том числе поверх
уже применённого патча RVC-1.

## Что сделано

### RVC-1 (уже было): запуск оригинального Ultimate RVC (Gradio) и показ во встроенном браузере
`core/rvc_process.py`, `ui/rvc_controller.py`, `ui/rvc_browser_page.py`, `ui/settings/rvc_page.py`.

### RVC-2 (новое)

**1. Выбор режима — списком на главном экране** (рядом с «Запустить»):
ComfyUI · Imagine · Imagine Pony · Ultimate RVC · Ultimate RVC (оригинал).
- Значение хранится в прежнем `cfg["interface"]` (старые config.json читаются без миграции),
  сохраняется сразу при выборе. `core/launch_mode.py` — список режимов, без Qt.
- Радиокнопки «Интерфейс» из настроек ComfyUI убраны; порты Imagine/Pony там теперь
  доступны всегда. `collect()` страницы больше не пишет `interface` (иначе автосохранение
  затирало бы выбор списка).
- «Запустить» в режимах RVC не требует папки ComfyUI и ничего не делает с ComfyUI.
  ComfyUI и RVC независимы: кнопка блокируется только если занят сервис выбранного режима.
- Для RVC на главном экране: прогресс запуска (общая полоса, «Отмена» останавливает RVC),
  зелёная полоса «Ultimate RVC запущен на порту N» с «Открыть / Остановить», живой вывод
  процесса в общую панель лога.
- «Ultimate RVC (оригинал)» — **пятый пункт, которого вы не просили**: в приложении Studio
  нет обучения моделей и части настроек оригинала, поэтому оставил Gradio-вариант.
  Если не нужен — убрать строку из `MODES` в `launch_mode.py`.

**2. Приложение «Ultimate RVC» в стиле Imagine** — `comfyui_studio/rvc/`:
- backend (FastAPI) запускается **питоном из venv RVC** (`python -m comfyui_studio.rvc`);
  torch в процесс Studio не попадает. Пакет Studio подкладывается через PYTHONPATH.
- Вкладки: **Кавер** (файл / ссылка YouTube / путь, все параметры `song_cover.run_pipeline`),
  **Озвучка** (Edge TTS → RVC), **Модели** (список, добавление из файлов, скачивание по
  ссылке, каталог публичных моделей, удаление). Справа — очередь с прогрессом, отменой,
  плеером и ссылками на промежуточные файлы (вокал, инструментал…).
- Один GPU-пайплайн за раз, остальные в очереди. Отмена — на границе этапов пайплайна.
- Тема и язык общие с комплектом (как у Imagine), пути в JS относительные (под будущий прокси).
- Запускается из Studio сразу (режим «Ultimate RVC» в списке на главном экране). **В Remote API не добавлено**, как просили.
- Лог вывода процесса: `%APPDATA%\ComfyUILauncher\rvc_last_run.log`.

Изменено для сборки: `ComfyUIStudio-core.spec`, `ComfyUIStudio-full.spec` — исходники
`comfyui_studio/rvc` кладутся в `rvc_app_src` как данные (внутри exe пакеты в архиве, питону RVC они
недоступны).

## Исправления после первого прогона (pytest + ручная проверка)

- **Оригинальный RVC открывал наше приложение и «не видел сервер».** Причина: оба режима
  открываются по одному адресу `127.0.0.1:<порт RVC>`, а у браузерной страницы RVC постоянный
  профиль с дисковым HTTP-кэшем — Chromium отдавал закэшированные `index.html`/JS нашего
  приложения вместо Gradio. Теперь `RvcBrowserPage` отключает HTTP-кэш и чистит старый
  (`rvc_browser_page.py`), а backend отдаёт `Cache-Control: no-store` (`rvc/backend/main.py`).
- **Кнопки запуска в настройках RVC убраны** (они же открывали «не ту» страницу): запуск и остановка
  только с главного экрана. В настройках остались параметры и строка состояния.
- **Запуск другого режима RVC при работающем** больше не переводит контроллер в `failed`
  (из-за этого пропадала полоса с «Остановить», а процесс жил дальше): теперь показывается
  сообщение, состояние не меняется.
- Тесты: `test_config_load_save` (в схеме конфига появился ключ `rvc`) и два теста
  `test_rvc_controller` (фикстура не создавала `python.exe`, нужный режиму `app`).

- Тесты без Qt: `test_rvc_process` (32), `test_rvc_app_backend` (29), `test_launch_mode` (6),
  `test_rvc_app_i18n` (2), `test_rvc_app_isolation` (3); `test_broad_except_budget`.
- Интерфейс прогнан в headless Chromium на **заглушке API**: вкладки, ошибка пустого задания,
  задание → очередь → прогресс → результат с `<audio>` (не пересоздаётся при опросе),
  озвучка, импорт модели, каталог, EN-язык, темы, сохранение формы между перезагрузками.

  поток (тест `test_unusable_runner_result_...`).

## НЕ проверено — смотреть у себя
1. **Qt-часть не запускалась** (нет PySide6): список режимов, полосы, `MainWindow`,
   `test_rvc_controller.py`, переписанный `test_comfyui_page_interface.py`. Прогоните целиком
   `pytest tests/launcher`.
2. **Реальный backend (`rvc/backend/main.py`) не запускался** — в песочнице нет fastapi/uvicorn
   и ultimate_rvc; проверены только его чистые части и UI на заглушке. Ручная проверка без Studio:
   ```
   cd D:\AI\ultimate-rvc
   $env:PYTHONPATH = "<папка проекта Studio>"
   uv\.venv\Scripts\python.exe -m comfyui_studio.rvc --port 7863
   ```
   и открыть http://127.0.0.1:7863 .
3. **Допущения об ultimate_rvc** (исходники `core/common.py` и `typing_extra.py` я не видел):
   - `display_progress()` вызывает `progress_bar(доля, desc=сообщение)` — на этом держатся
     прогресс и отмена. Запасной канал: лог-сообщения `[~] …` (этап виден, но без процента и
     без отмены).
   - В `typing_extra` есть `F0Method.RMVPE`, `EmbedderModel.CONTENTVEC`, `AudioExt.MP3` (взяты из
     значений по умолчанию в присланных сигнатурах); остальные члены перечислений читаются из
     самих классов, не зашиты.
   - `get_edge_tts_voice_names()` требует интернет; без него вкладка «Озвучка» покажет ошибку.
4. Скачивание файла из `<audio>`/ссылок во встроенном браузере (диалог «Сохранить как»).
5. Сборка PyInstaller (datas `rvc_app_src`) не пробовалась.
6. Свой эмбеддер (`custom`) в интерфейсе скрыт — в этой версии не поддерживается.
